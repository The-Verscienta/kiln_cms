# What's new in Kiln 1.11

Kiln 1.11 was released on YYYY-MM-DD. Below: what it adds, what works
differently, what to do before you upgrade, and what is still broken. Every
change, one line each, is in the [1.11.0 changelog](../changelog/unreleased.md).

## At a glance

- **Platform admins** can send in-app backups to several destinations at
  once (a directory on the server, an rclone remote, S3-compatible storage
  or a plugin's), resume a cut-off upload, and re-send a backup to the
  destinations it missed.
- **Admins** can build pages from **Flexible content**: an ordered list of
  items of different kinds (a hero, a quote), each with its own fields and
  settings, edited as cards.
- **Admins** get new field options: a built-in **Address** type, number
  steps, units and a slider, color palettes, JSON Schema checks, and record
  titles built from a template.
- **Site admins** are told, in the bell and by email, when a webhook stops
  getting through or is switched off.
- **API clients** can group GraphQL `customWhere` conditions with `_or`,
  `_and` and `_not`, and sort by a reference or media field.
- **Everyone** gets a more thorough erasure: an erased person's newsletter
  subscriptions, memberships, queued mail and leftover API keys go with the
  account.

## Before you upgrade

Read the [Upgrade notes and Breaking sections](../changelog/unreleased.md) in
full; `mix kiln.update` prints them, and the known issues, before it moves
your pin. In short:

1. **Run `mix ash.migrate`.** It adds the tables `backup_destinations`,
   `backup_notices` and `backup_uploads`, and nullable columns on
   `field_definitions`, `type_definitions`, `backup_runs`,
   `backup_node_beats` and `users`, and re-creates the `kiln_reporting_v1`
   views. None of them rewrites a table, and rolling back is safe.
2. **Finish a rolling deploy before you start, cancel, resume or re-send a
   backup.** Nodes on 1.10 don't know the new backup steps and per-directory
   queues. Before rolling back, cancel running backups and re-sends.
3. **Copy the new `scripts/backup.sh` and `scripts/restore.sh` to every host**
   that runs them. Older copies don't recognize the new temporary file names.
   Backups now check free space first (`BACKUP_FREE_SPACE_CHECK=false` turns
   that off), give up on a table lock after `BACKUP_LOCK_WAIT_SECONDS`, and
   refuse a database URL with `sslpassword`.
4. **Drain the `mail` queue before rolling back.** Form, workflow and task
   mail jobs now carry ids, which 1.10 can't send.
5. **Expect boot-time jobs.** About ten minutes after boot, the erasure
   backfill tidies accounts erased before this release (newsletter rows,
   memberships, API keys and more), and a daily job drops form data and
   automation payloads from finished jobs (`KILN_PRIVATE_ARGS_SCRUB_CRON`).
6. **Overlays and plugins:** `address` and `flexible` are now built-in field
   type names; rename a type of your own that uses either. A plugin that
   owns tables needs `staging_scrub/0` entries before `mix
   kiln.staging.scrub` will run (see Breaking changes).
7. **Field sync across versions:** a file exported by 1.11 doesn't import
   into 1.10.x. Upgrade environments together, or strip the new keys first
   ([field-sync.md](../field-sync.md#what-an-older-build-refuses-in-a-new-export)).

## New features

### Backup destinations, S3 and Re-send

An in-app backup can now go to several places, not only
`BACKUP_RCLONE_REMOTE`: a directory on this server (a NAS mount, a second
disk), a named rclone remote, an S3-compatible bucket (AWS S3, R2, B2,
Wasabi, MinIO, Garage), or a kind a plugin adds. Each destination is tested
before it's used and pruned of only what this installation sent. A backup
that reaches some destinations succeeds as **Partly off-site** and raises
the alarm. S3 uploads go up in parts and resume where they stopped.

**In the console:** **Backups** → **Destinations** (`/editor/backups/destinations`,
platform admins) → **Add a destination**, pick **What kind of destination?**,
fill in the form, then **Test**. Later, in **History**, a backup badged
Partly off-site or Not off-site gets **Re-send**, which sends its files to
the destinations it missed, checking each against its checksum first.

Schedules can also run every 2, 4, 8 or 12 hours, History badges the backups
a schedule keeps, and the Backups page warns when retention was skipped or a
kept backup was deleted outside the app.

Read more: [Send backups to several destinations](../backups.md#send-backups-to-several-destinations),
[Back up to S3-compatible storage](../backups.md#back-up-to-s3-compatible-storage),
[Re-send a partly off-site backup](../backups.md#re-send-a-partly-off-site-backup).

### Flexible content

A **Flexible content** field holds an ordered list of items of different
kinds, each kind with its own fields. Settings (a background, a width) are
kept apart from content under `_settings`. Your theme decides how each kind
looks.

**In the console:** **Fields** (`/editor/fields`, admins) → **Add a field**,
choose **Flexible content** as the **Field type**, save, then use the row's
**Item types** panel → **Add an item type**. Editors fill it in as cards
with **Add item** in the content editor.

**Through the API**, a write sends the whole list; each item names its
`_type`, and Kiln gives it an `_id` to send back. The shape comes from
`test/kiln_cms/cms/flexible_write_test.exs`:

```json
"custom_fields": {
  "sections": [
    {"_type": "hero", "headline": "Hello", "_settings": {"background": "dark"}},
    {"_type": "quote", "text": "Be brief", "cite": "Me"}
  ]
}
```

Read more: [Build flexible content in the admin](../extending-content.md#build-flexible-content-in-the-admin),
[Address and flexible values](../json-api.md#address-and-flexible-values).

### New field options

- **Address.** A built-in type that stores a postal address as one object,
  with a country select and a postal-code check for 14 countries
  ([Address fields](../extending-content.md#address-fields)). Written over
  JSON:API as (shape from `test/kiln_cms/cms/address_field_test.exs`):

  ```json
  "office": {"country": "ca", "postal_code": "k1a0b1", "locality": " Ottawa ",
             "administrative_area": "ON", "address_line1": "80 Wellington St"}
  ```

  and stored as `{"country": "CA", "postal_code": "K1A 0B1", "locality": "Ottawa", …}`.
- **Numbers:** **Step**, **Prefix** and **Suffix**, and a **Slider** input
  ([Show a number as a slider or with a unit](../extending-content.md#show-a-number-as-a-slider-or-with-a-unit)).
- **Color palettes and JSON Schema.** Limit a color field to a palette, shown
  as swatches, or check a JSON field against a JSON Schema
  ([Constrain the values of a field](../extending-content.md#constrain-the-values-of-a-field)).
- **Title templates.** A content type can build every record's title from
  its fields, for example `{{ field.last_name }}, {{ field.first_name }}`;
  editors no longer type one
  ([Build record titles from fields](../extending-content.md#build-record-titles-from-fields)).

### Webhook failure alerts

Site admins get a notice in the bell and an email when an endpoint's first
delivery exhausts its retries ("A webhook is failing") and when it is
auto-disabled ("A webhook was switched off"). A flapping receiver gives one
notice, not one per publish. Turn the email off under **Your settings** →
**Email notifications** → **Webhook failures**.

Read more: [Failure alerts](../webhooks.md#failure-alerts).

### Boolean groups in GraphQL `customWhere`

`customWhere` takes `_or`, `_and` and `_not` groups, the typed form of
`customFilter`'s, with the same caps (4 deep, 50 conditions). From
`test/kiln_cms_web/graphql_custom_where_test.exs`:

```graphql
customWhere: [
  { name: "price", float: { lt: 50 } }
  { _or: [
      { name: "color", string: { eq: "red" } }
      { _not: { name: "stock", int: { gt: 0 } } }
  ] }
]
```

Read more: [Typed filters: `customWhere`](../headless-graphql-api.md#typed-filters-customwhere).

### Also new

- Import field definitions from the console: upload a file, review the
  dry-run diff, confirm `--prune` and `--allow-data-loss` separately, and
  apply ([Import from the console](../field-sync.md#import-from-the-console)).
  ([#2961](https://github.com/The-Verscienta/kiln_cms/pull/2961))
- `custom_sort` / `customSort` and the content list's **Sort by** can use a
  single-valued reference or media field, by the target's current title or
  filename. ([#2960](https://github.com/The-Verscienta/kiln_cms/pull/2960),
  [#2963](https://github.com/The-Verscienta/kiln_cms/pull/2963))
- `kiln_plugin` 1.5.0: plugins can add backup destinations
  (`Kiln.BackupDestination`) and declare what the staging scrub does to
  their tables (`staging_scrub/0`)
  ([plugin-extensibility.md](../plugin-extensibility.md)).
- Export my data lists the account's site memberships and newsletter
  subscriptions.

## Changes

- **Erasure goes further.** Before, an erased person kept newsletter
  subscriptions, site memberships and queued mail. Now erasure deletes the
  subscriptions, demotes every membership, withholds queued account,
  workflow and task mail, and blocks giving the account a role again
  ([data-flows.md](../data-flows.md)).
- **Mail checks again when it sends.** Workflow and task mail is not sent for
  an event muted, content trashed or a task completed since it was queued,
  nor to a suppressed address; form mail is built from the stored
  submission, so one deleted or marked spam first sends nothing.
- **The staging scrub removes more:** newsletter subscribers, form
  submissions, suppression lists, federation followers and keys, per-site
  integrations and every queued job. Re-scrub any clone made before 1.11
  before you share it ([staging-environments.md](../staging-environments.md#the-scrub)).
- **Account emails name people by display name.** The API key reuse and
  factor-removal emails no longer show anyone's email address.
- **Backup steps run where their files are.** Steps that need a backup
  directory go to that directory's own Oban queue, `backup_dir_<id>`.

## Breaking changes

### Scrubbing a serving node over `rpc`

**Who is affected:** operators who scrub a staging clone with
`bin/kiln_cms rpc 'KilnCMS.Staging.scrub!(…)'` on a node that is already
serving. It now raises "Refusing to scrub from a node whose Oban queues are
running."

**Before:**

```bash
bin/kiln_cms rpc 'KilnCMS.Staging.scrub!()'
```

**After:** scrub a new clone before it serves, or pass `allow_live?: true`
to re-scrub one (every queue pauses until restart):

```bash
bin/kiln_cms eval 'KilnCMS.Release.scrub_staging()'
bin/kiln_cms rpc 'KilnCMS.Staging.scrub!(allow_live?: true)'
```

### The staging scrub refuses undeclared plugin and overlay tables

**Who is affected:** sites that clone production into staging and run a
plugin or overlay domain that owns tables. `mix kiln.plugins.doctor` lists
each undeclared table. To fix it, declare every table in the plugin's
`staging_scrub/0` and require `{:kiln_plugin, "~> 1.5"}`.

**Before:** no callback; the scrub copied these tables untouched.

**After:**

```elixir
@impl Kiln.Plugin
def staging_scrub do
  [
    {:purge, MyPlugin.Subscriber},
    {:rewrite, MyPlugin.Contact, set: [email: nil]},
    {:keep, MyPlugin.Setting, "no personal data"}
  ]
end
```

See [Plugin tables](../staging-environments.md#plugin-tables).

### Field sync refuses a section entry no field carries

**Who is affected:** deploy scripts that import a hand-edited or generated
field-sync file. A file from `mix kiln.fields.export` is never refused. The
dry run, the console preview and `--apply` now refuse the whole file:

```text
ERROR post/section/Clinical: no field of post is in this section, so its layout lays nothing out
```

**Before:** the entry stored a layout that the next field filed under that
name took on. **After:** put a field in the section, fix the name, or drop
the entry ([field-sync.md](../field-sync.md#a-section-entry-no-field-carries)).

### Scheduled actions change only a record that is due

**Who is affected:** overlay or plugin code and tests that call
`:publish_scheduled`, `:unpublish_scheduled` or `:archive_scheduled`
directly on a record whose date hasn't passed. They now return an
`Ash.Error.Invalid` holding a `StaleRecord` and change nothing. The cron
and the APIs are not affected.

**Before** (a page whose `scheduled_at` is still in the future):

```elixir
CMS.publish_scheduled_page!(page)
```

**After:** call the action for "now", or set `scheduled_at` in the past
first, as Kiln's own tests do:

```elixir
CMS.publish_page!(page)
```

## Deprecations

- `KilnCMS.Backups.Worker`, `KilnCMS.Backups.enqueue/1` and the `backups`
  Oban queue are still deprecated and still present in 1.11. Call
  `KilnCMS.Backups.request/2` instead, and drain the `backups` queue before
  upgrading to the release that removes them, which its changelog will name.

## Known issues

- **Two referrer breakdowns of overlapping traffic can be differenced to
  recover a suppressed count.** Affects sites with
  `KILN_ANALYTICS_REFERRERS` on. No workaround short of turning it off.
  Tracked in [#2989](https://github.com/The-Verscienta/kiln_cms/issues/2989).
- **Pending automation jobs hold the event's document, drafts included, in
  plain text**, and so do Oban's `job:start` / `job:stop` log lines. No
  workaround short of logging above `info`. Tracked in
  [#2992](https://github.com/The-Verscienta/kiln_cms/issues/2992).
- **A scrubbed staging clone keeps production's S3 storage credentials and
  provenance signing key.** Start every clone with its own
  `SECRET_KEY_BASE`, so it can't decrypt them. Tracked in
  [#2973](https://github.com/The-Verscienta/kiln_cms/issues/2973) and
  [#2974](https://github.com/The-Verscienta/kiln_cms/issues/2974).
- **`scripts/staging.sh up` with the default `KILN_BIN=mix` migrates the dev
  database unless `MIX_ENV=prod` is set.** Export `MIX_ENV=prod`, or point
  `KILN_BIN` at a release. Tracked in
  [#2977](https://github.com/The-Verscienta/kiln_cms/issues/2977).
- **GraphQL `customWhere` with `dateTime` can miss date-time list items saved
  with fractional seconds.** Use `custom_filter` on the REST API. Tracked in
  [#2678](https://github.com/The-Verscienta/kiln_cms/issues/2678).
- **On a site other than the default one, New draft and Translations can be
  offered or hidden by the default site's type scope.** Saving is still
  checked correctly. Tracked in
  [#2599](https://github.com/The-Verscienta/kiln_cms/issues/2599).
- **Lock and teaser pages, embedded forms and newsletter confirmation mail
  can be in the wrong language on a multilingual site.** Tracked in
  [#2597](https://github.com/The-Verscienta/kiln_cms/issues/2597).
- **A gallery carousel can't be scrolled with the keyboard.** Use the grid
  layout where that matters. Tracked in
  [#2590](https://github.com/The-Verscienta/kiln_cms/issues/2590).
- **The sign-in page on a site's own address offers "Use a passkey", which
  fails there.** Sign in on the main or console host. Tracked in
  [#2827](https://github.com/The-Verscienta/kiln_cms/issues/2827).
- **"Confirm it's you with your passkey" shows no passkey button** in a
  browser without WebAuthn. Use another browser or a recovery code. Tracked
  in [#2887](https://github.com/The-Verscienta/kiln_cms/issues/2887).
- **A recurrence rule with a date-time `UNTIL` can end a day early or
  late.** Write `UNTIL` as a date. Tracked in
  [#2861](https://github.com/The-Verscienta/kiln_cms/issues/2861).
- **A member who starts checkout again for the tier they hold drops to
  "incomplete".** The provider's next update restores a paid membership.
  Tracked in [#2747](https://github.com/The-Verscienta/kiln_cms/issues/2747).
