# What's new in Kiln 1.12

Kiln 1.12 was released on 2026-11-21. Below: what it adds, what works
differently, what to do before you upgrade, and what is still broken. Every
change, one line each, is in the [1.12.0 changelog](../changelog/v1.12.0.md).

## At a glance

- **Platform admins** can send backups to any SFTP server, with a host key
  they confirm before the first upload, and destination retention now
  deletes only the backups this server sent.
- **Plugin authors** can make a field type hold a list, with the same
  editor input, write rules, API filters and schema export as Kiln's own
  list fields.
- **Headless front ends** can read a site's name, X handle and default share
  image from `GET /api/site` for their link-preview tags.
- **Operators** can watch each installed plugin's health from a monitor
  through `GET /api/security/plugin-health`.
- **AI clients on `/mcp`** can read, create and relabel links between
  records.
- **Site owners** can show an embedded form in a chosen language with
  `data-kiln-locale`.

## Before you upgrade

Read the [Upgrade notes and Breaking sections](../changelog/v1.12.0.md) in
full; `mix kiln.update` prints them, and the known issues, before it moves
your pin. In short:

1. **Run `mix ash.migrate`.** It adds nullable columns to `backup_runs`
   (`keep_days`), `billing_memberships` (`last_provider_event_at`),
   `backup_destinations` (`host_key`) and `backup_uploads` (`dir_id`), and an
   `adoptions` list on `backup_destinations` that defaults to empty. None of
   them rewrites a table, and rolling back is safe.
2. **Re-scrub every staging clone made before 1.12**
   (`./scripts/staging.sh scrub`). Older clones still hold production's S3
   storage credentials and content-signing key. `staging.sh` with
   `KILN_BIN=mix` now runs under `MIX_ENV=prod` and needs `SECRET_KEY_BASE`
   and `TOKEN_SIGNING_SECRET`
   ([staging-environments.md](../staging-environments.md#the-scrub)).
3. **Check your backup destinations' storage after the upgrade.** Retention
   now deletes only what this server's backup directory sent. Backups made
   before 1.10, and those sent from a `BACKUP_DIR` that didn't survive a
   redeploy, are kept from now on until you adopt their directory on the
   **Destinations** tab or prune them by hand. Two S3 destinations whose
   prefixes nest on one bucket name stop pruning, with a notice, until you
   separate them.
4. **A plugin destination of kind `sftp`** is now answered by Kiln's own
   adapter: delete such rows and add them again under **SFTP server**. List
   LAN SFTP servers in `BACKUP_SFTP_PRIVATE_HOSTS`.
5. **Custom asset builds** that don't run `mix assets.deploy` should also run
   `mix esbuild kiln_public --minify` before `phx.digest`. Without it,
   signed-out pages fall back to app.js and keep working.
6. **Before rolling back past 1.12** with plugin list fields in use, find
   them first ([Rolling back past plugin list fields](../releasing.md#rolling-back-past-plugin-list-fields)):
   older releases treat them as single values.
7. **GraphQL clients** that filter `dateTime` custom fields, and websocket
   clients that send a lowercase `bearer`, read the Breaking changes below.

## New features

### SFTP backup destinations

Platform admins can send each in-app backup to a folder on any host that
speaks SFTP: a NAS, a storage box, a server running OpenSSH. Kiln signs in
with a password or a private key (Ed25519, ECDSA, or RSA of 2048 bits or
more), resumes a cut-off upload, and prunes and rescans as it does for S3.

**In the console:** *Backups → Destinations → Add a destination → SFTP
server* (platform admins only). Fill in **Host**, **Port**, **Username**,
**Path** and a **Password** or **Private key**, then save. The destination
is saved disabled. On its row, choose **Check host key**, compare the
fingerprint with the one the server prints for
`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`, and confirm it. If the
server's key later changes, the destination fails and platform admins are
alerted.

Read more: [Back up to an SFTP server](../backups.md#back-up-to-an-sftp-server).

### Plugin field types that hold a list

A plugin field type can now take a list of values, the way Kiln's own
`string` or `number` fields can. Define `multiple?/0` to return `true`, and
`unique_items?/0` to drop repeated items. `cast/2` still sees one item at a
time. This needs `kiln_plugin` 1.6.

This field type, from Kiln's test fixtures, holds a list of short tags:

```elixir
defmodule MyPlugin.FieldTypes.Tag do
  use Kiln.FieldType

  @impl Kiln.FieldType
  def multiple?, do: true

  @impl Kiln.FieldType
  def unique_items?, do: true

  @impl Kiln.FieldType
  def graphql_kind(_definition), do: :string

  @impl Kiln.FieldType
  def json_schema(_definition), do: %{"type" => "string", "maxLength" => 40}

  @impl Kiln.FieldType
  def cast(value, _definition) when is_binary(value) do
    case value |> String.trim() |> String.downcase() do
      "" ->
        {:error, "must not be blank"}

      tag ->
        if String.length(tag) > 40,
          do: {:error, "must be at most 40 characters"},
          else: {:ok, tag}
    end
  end

  def cast(_value, _definition), do: {:error, "must be a tag"}
end
```

If a type later stops taking lists, a field that already holds a list keeps
it read-only (a "held list") instead of losing it.

Read more: [Let a plugin field type take a list](../extending-content.md#let-a-plugin-field-type-take-a-list).

### Site defaults for link previews: `GET /api/site`

A headless front end can read the values it needs for its Open Graph and X
card tags when a document has none of its own. No credential is needed, and
the answer is shared-cacheable; a Branding save that changes one of them
purges it from the CDN.

```bash
curl -s https://<your-site>/api/site
```

```json
{
  "site_name": "Acme Docs",
  "twitter_site": "@acme",
  "social_image_url": "https://cdn.test/card.png"
}
```

An unbranded site answers `"KilnCMS"` and two `null`s. (Shape copied from
`test/kiln_cms_web/controllers/site_controller_test.exs`.)

Read more: [Site defaults](../api.md#site-defaults).

### Plugin health for monitors: `GET /api/security/plugin-health`

The plugin check that System and Security posture show is now available as
JSON, one entry per plugin, so a monitor can alert on one plugin rather than
on the summary line. It needs a read-only API key owned by a platform
administrator, passes the host site's admin allowlist, and reads only the
server's cache: it never asks hex.pm itself.

```bash
curl -s https://<your-site>/api/security/plugin-health \
  -H "authorization: Bearer <api-key>"
```

Alert on `counts.fail` above zero, and key plugins on `id`. A server that
hasn't checked yet answers `"state": "not_checked"`.

Read more: [Monitor each plugin from a script](../security-posture.md#monitor-each-plugin-from-a-script)
and [Plugin health (monitoring)](../api.md#plugin-health-monitoring).

### Links between records over `/mcp`

`/mcp` gains `read_content_links`, `create_content_link` and
`update_content_link`, over the same links `/api/json/content-links` writes.
Writing a link is authorized as an edit of its source record. A read key is
offered only the read tool. There is no delete tool.

```json
{"name": "create_content_link", "arguments": {"input": {
  "source_id": "<post id>", "target_id": "<other record id>",
  "kind": "related", "position": 2, "label": "Background"}}}
```

Overlays that replace `:mcp_tools` must add the three tools themselves.
(Call copied from [mcp.md](../mcp.md#tools).)

Read more: [MCP tools](../mcp.md#tools).

### Also new

- **Embedded forms in a chosen language.** Add `data-kiln-locale` to the
  snippet:
  `<script src="https://<your-site>/embed.js" data-kiln-form="contact" data-kiln-locale="fr"></script>`.
  An unsupported value gets the site default, and existing snippets are
  unchanged ([forms.md](../forms.md#embedding-on-another-site)).
- **Backups → Schedule** warns when a schedule would keep more than about
  500 backups of each component, or more than the backup directory has room
  for. It never blocks the save ([backups.md](../backups.md)).

## Changes

- **Signed-out pages load a smaller script.** Before, a content page loaded
  the 81 KB app.js and its chunks. Now it loads a 2.5 KB (gzipped)
  `public.js`, and `mix kiln.assets.budget` fails a build that pulls
  LiveView or console code into it
  ([frontend-assets.md](../frontend-assets.md)).
- **A cut search lets running sections finish.** Before, a search over
  `query_budget` killed its running sections at once. Now they get
  `cut_grace` (100 ms by default) to stop on their own, so a query that
  finishes keeps its database connection; a cut search may answer up to that
  much later ([api.md](../api.md#search-budget-and-server-timing)).
- **Referrer figures are exact or hidden.** Before, two overlapping referrer
  breakdowns could be differenced to recover a suppressed count. Now every
  figure wider than one item-day is built from the per-day figures (a source
  reads `hidden` for the range if any day hid it), and only completed UTC
  days are shown or exported
  ([environment-variables.md](../environment-variables.md)).
- **Staging clones get their own storage and signing key.** The scrub now
  removes production's S3 storage credentials (existing media still loads
  from production's public URLs; new uploads go to staging's own storage)
  and its content-signing key; staging generates its own
  ([staging-environments.md](../staging-environments.md#the-scrub)).
- **`bearer` in any case authenticates.** A valid `bearer <jwt>` or
  `BEARER <jwt>` now works on `/api/*`, `/gql` and `/api/feed`, reversing
  1.9.0's `401`; `/mcp` and key rotation take a `kiln_` key under any case
  ([api.md](../api.md)).

## Breaking changes

### GraphQL `customWhere` `dateTime` operands are `NaiveDateTime`

**Who is affected:** GraphQL clients that filter a `datetime` custom field
with `customWhere`. To check, search your queries for `dateTime:` inside a
`customWhere`, and for variables declared `DateTime` that feed one.

A `datetime` field is stored without its UTC offset, and the filter now
compares the same way: an operand's offset is dropped, not converted. A
variable for an operand must be declared `NaiveDateTime`.

**Before:**

```graphql
query ($from: DateTime) {
  publishedPosts(customWhere: [{ name: "starts_at", dateTime: { gte: $from } }]) {
    results { id }
  }
}
```

**After:**

```graphql
query ($from: NaiveDateTime) {
  publishedPosts(customWhere: [{ name: "starts_at", dateTime: { gte: $from } }]) {
    results { id }
  }
}
```

`{eq: "2026-06-01T12:00:00+02:00"}` now finds a value saved as
`2026-06-01T12:00:00`, not one saved as `…T10:00:00Z`. Write operands in the
wall-clock time you stored. (Query copied from
[headless-graphql-api.md](../headless-graphql-api.md#typed-filters-customwhere).)

### `/ws/gql` reads `bearer` in any case

**Who is affected:** websocket clients that pass an `authorization` connect
param whose scheme isn't written `Bearer`. To check, look at the connect
params your client sends.

**Before:** `{"authorization": "bearer <jwt>"}` connected anonymously, and so
did `{"authorization": "bearer <garbage>"}` or a bare `"Bearer"`.

**After:** `{"authorization": "bearer <jwt>"}` connects as the token's user;
`{"authorization": "bearer <garbage>"}` and a bare `"Bearer"` are refused with
`403`. A client that relied on the anonymous fallback should drop the param.

## Known issues

- **With many Hex plugins and a slow hex.pm, the same plugins at the end of
  the list read Unknown on every check.** Affects platform administrators on
  deployments with enough Hex plugins that a check doesn't finish in 75
  seconds. Until it is fixed, check those packages on hex.pm by hand.
  Tracked in [#3165](https://github.com/The-Verscienta/kiln_cms/issues/3165).
- **A site storage profile on a region ExAws doesn't know fails on every
  upload and read.** Affects sites whose storage profile points at Backblaze
  B2 (`us-west-004`), Wasabi (`us-central-1`) or similar. Until it is fixed,
  keep those sites on the instance's storage. Backup destinations are not
  affected. Tracked in [#3085](https://github.com/The-Verscienta/kiln_cms/issues/3085).
- **Comping a member whose subscription is still active doesn't cancel it.**
  The provider keeps charging, and its later events are ignored. Until it is
  fixed, cancel the subscription in the provider's dashboard before you comp
  the member. Tracked in [#3156](https://github.com/The-Verscienta/kiln_cms/issues/3156).
- **A page opened at its path alias shows no reference byline and leaves
  inherited fields blank.** The same page at its slug shows both. Until it
  is fixed, link to the slug where that matters. Tracked in
  [#3193](https://github.com/The-Verscienta/kiln_cms/issues/3193).
