# What's new in Kiln 1.9

Kiln 1.9 was released on 2026-11-11. Below: what it adds, what works
differently, what to do before you upgrade, and what is still broken. Every
change, one line each, is in the [1.9.0 changelog](../changelog/v1.9.0.md).

## At a glance

- **Site admins** can see their security settings scored at a glance, read a
  security log of who signed in and changed what, and get an email when
  something risky happens.
- **Site admins** can hold new sign-ups for approval, invite people by email,
  sign idle browsers out, restrict the console to listed networks, and ask
  for a human-verification check on sign-in and on public forms.
- **Admins** get a much stronger custom-field model: constraints, conditions,
  dynamic defaults, lists of any scalar type, nine new field types, a choice
  of editor input, and tabbed or sectioned layouts. The content list can show,
  filter, sort and export those fields.
- **Platform admins** get backups they can follow: a History of every attempt,
  media archives in resumable parts, Cancel and Resume, a cluster-wide lock,
  and database-only or media-only backups from a console.
- **Developers** get typed client contracts (OpenAPI components, Swift and
  Kotlin models, a `--check` for CI) and a Server-Sent Events change feed at
  `GET /api/feed`.

## Before you upgrade

This release has many migrations and several behavior changes that are on by
default. Read the [Upgrade notes and Breaking sections](../changelog/v1.9.0.md)
in full; `mix kiln.update` prints them before it moves your pin. In short:

1. **Run `mix ash.migrate`.** It adds tables for the security logs and alerts,
   registrations, invitations, backups, field sections, sessions, the admin
   allowlist and bot budgets, plus columns on users, field definitions and
   content tables. Two steps rewrite or build over whole tables on a large
   site: the generated `name_lexemes` column on content tables (a table
   rewrite) and the `custom_fields` GIN index (built concurrently). Overlays
   run `mix ash.codegen` first and commit the migration.
2. **Overlays that restate `:ash_domains`** add `KilnCMS.Security` and
   `KilnCMS.Backups`.
3. **Check what now calls out by default:** the breached-password check
   (Have I Been Pwned), DNS lookups to verify search-engine crawlers, and the
   plugin health check against hex.pm. Each has an off switch, listed in
   [System requirements → Outbound calls made by default](../system-requirements.md#outbound-calls-made-by-default).
4. **API clients** that send a stale or garbled `Authorization: Bearer` token
   now get `401` `invalid_token` instead of anonymous data. Fix the client;
   `KILN_API_REJECT_INVALID_BEARER=false` restores the old fallback for this
   release only.
5. **Backups:** if `BACKUP_RCLONE_REMOTE` is set, check it before deploying,
   because the official image now ships `rclone` and starts copying there. Add
   one to `POOL_SIZE` for the new `backup_steps` queue, and update the host's
   copy of `scripts/backup.sh`.
6. **Editors on upgraded sites lose Unpublish and Archive** until an admin
   chooses **Let editors publish** (see Breaking changes below).
7. **After deploying,** optionally run `mix kiln.refire_all` so pages fired
   before the upgrade pick up the new focusable code blocks and tables, link
   preview tags and `json` artifact `social` key.
8. **Confirmation links now ask for the password chosen at sign-up.** Links
   mailed before the upgrade keep working. A client that posts to
   `/auth/user/confirm_new_user` itself must send `password` with the token.

Rolling the pin back to 1.8.0 is possible but takes cleanup first: the
changelog's *Before rolling back to v1.8.0* note lists the rows to delete. The
upgrade was rehearsed from 1.6.0, 1.7.0 and 1.8.0.

## New features

### Security posture, security log and alerts

Three new pages under **Organization** in the console, for site admins:

- **Security posture** (`/editor/security-posture`) lists the site's security
  settings with a status for each (**Fix now**, **Review**, **OK**) and says
  what to fix first. Platform admins also see the installation's checks:
  Kiln's version, published security notices for Kiln, and installed plugins.
- **Security log** (`/editor/security-log`) records who signed in, was locked
  out, or changed a second factor, passkey, role, API key or sign-in setting,
  and from where. Platform admins also get an **Instance security log** for
  events about the whole installation.
- **Security alerts** (`/editor/security-alerts`) sends site admins a bell
  notice and an email when someone becomes an admin, a role is raised, an
  account is locked out, two-factor is turned off or single sign-on changes.

The posture is also available as JSON for a monitor, with a read-only API key
owned by an administrator:

```bash
curl -s https://cms.example.com/api/security/posture \
  -H "authorization: Bearer $KILN_API_KEY"
```

Alert on `"status": "fail"`. A `warn` right after a deploy often clears within
a minute.

Read more: [Security posture](../security-posture.md),
[Security log](../security-events.md), [Security alerts](../security-alerts.md).

### Control who gets in

New pages under **Sign-in & access**, for site admins:

- **Registrations**: tick **New registrations wait for an administrator's
  approval**, then Approve or Reject each applicant. Admins are notified when
  a confirmed applicant is waiting, and applicants are emailed the decision.
- **Admin allowlist**: restrict the console and every sign-in route to listed
  IPv4/IPv6 networks.
- **Sessions**: sign idle browsers out after 15 minutes to 24 hours, and sign
  everyone out of the site at once.
- **Password policy**: choose what happens to a password found in a breach:
  off, warn (default) or block for administrators.

Platform admins can also invite someone with no account by email from
**Team → Add or invite**. A person whose sign-in is paused can have an unlock
link emailed from the sign-in page. Operators can turn on an adaptive
Cloudflare Turnstile or Google reCAPTCHA check for sign-in and registration
with `CHALLENGE_PROVIDER`, `CHALLENGE_SITE_KEY` and `CHALLENGE_SECRET_KEY`.

Read more: [Account administration](../account-administration.md#approving-registrations),
[Admin allowlist](../admin-allowlist.md),
[Human verification](../human-verification.md).

### Custom fields that check, adapt and lay themselves out

In **Content model → Fields** (`/editor/fields`), admins can now:

- **Constrain values** with `min`/`max`, a length range, a whole-value
  `pattern` with its own message, or `unique`, enforced on every write path;
- show or require a field only when another field has a given value
  (**Conditions**);
- default a field to today, now, the creating user, the site locale or
  another field (**Default comes from**);
- make number, date, URL, email, telephone, color and slug fields hold a list
  (**Holds → A list**);
- pick the editor input (radios, buttons, checkboxes, a reference dropdown);
- lay fields out as tabs, fieldsets or accordions with full, half or a third
  width (**Sections of**).

Nine new built-in types check and tidy their values: `email`, `telephone`
(E.164), `color`, `slug`, `time`, `json`, `range`, `key_value` and `link`.
Roles and members can be granted individual fields, and definitions move
between environments with `mix kiln.fields.export` and `mix kiln.fields.import`.

A field definition with constraints, sent through the API:

```json
{"field_type": "string", "name": "sku", "label": "SKU",
 "validation": {"pattern": "[A-Z]{3}-[0-9]{4}", "pattern_message": "Use three capitals, a dash and four digits.", "unique": true}}
```

Saving `{"sku": "abc"}` then fails with
`SKU (sku): Use three capitals, a dash and four digits.`

Once one content type is listed, the content list can show up to four custom
fields as columns, filter on up to four conditions, sort by one, and export
the rows as CSV or JSON.

Read more: [Extending content](../extending-content.md#constrain-the-values-of-a-field),
[Field sync](../field-sync.md).

### Backups you can follow

In **Operations → Backups** (platform admins):

- **History** lists every attempt, app- and cron-made, with its verified
  state and whether its files are still on disk.
- Media backups are split into independent `tar.gz` parts with SHA-256
  sidecars. A failed run gets a **Resume** button, and `restore.sh media`
  restores a multi-part set.
- Backups run as retried steps behind a cluster-wide lock: a second request
  queues, a stopped node's step moves on, and a running backup can be
  canceled.
- Retention keeps the newest good backup of each component and honors
  `kiln-<stamp>.keep` recovery points.

To back up only the database, for example before a risky migration, run on a
running node:

```bash
bin/kiln_cms rpc '{:ok, result} = KilnCMS.Backups.request([trigger: "console", components: [:db]], KilnCMS.Backups.system()); IO.inspect(result)'
# %{status: :started, chain: "5f0c7c1e-…"}
```

**Back up now** in the console still backs up everything.

Read more: [Backups](../backups.md#back-up-only-the-database-or-only-the-media).

### Typed client contracts and a live change feed

`GET /api/schema` now serves the delivery schema in more shapes:
`?format=openapi` (OpenAPI 3.1 components with explicit discriminator
mappings), `swift`, `kotlin` (with `?package=`) and `typescript-graphql`.
`mix kiln.export.schema --check PATH` fails CI when a committed file has
drifted from the live schema.

```bash
curl -s 'http://localhost:4000/api/schema?format=openapi&blocks=only' \
  | jq '.components.schemas.block.discriminator.mapping.heading'
# "#/components/schemas/block_heading"
```

`GET /api/feed` streams publishes, updates and withdrawals as Server-Sent
Events, carrying identifiers only. Each event id is also an `/api/sync`
cursor, and a client that reconnects with `Last-Event-ID` gets what it
missed:

```bash
curl -N -H 'Accept: text/event-stream' 'https://cms.example.com/api/feed?type=post'
```

```text
event: published
id: SFMyNTY…
data: {"affected":[],"id":"6f1c…","locale":"en","published_at":"2026-11-10T09:30:00Z","slug":"hello","type":"post"}
```

Read more: [API → Schema discovery](../api.md#schema-discovery-typed-clients),
[API → Change feed](../api.md#change-feed-sse),
[Following the change feed](../headless-consumer-guide.md#live-updates-follow-the-change-feed).

### Also new

- Public delivery throttles by user-agent class, verifies search-engine
  claims by DNS, and can block an address that probes for 404s; site admins
  can block IP ranges at **Sign-in & access → Blocked addresses**.
- Forms gain `radio`, `checkboxes`, `phone`, `url`, `hidden`, `number` and
  `rating` fields, and an optional human-verification check per form.
- Drafts-only API keys (`access: draft_write`) let a headless service create
  and edit its own drafts, and can rotate themselves through
  `POST /api/keys/rotate`.
- GraphQL `customWhere` filters custom fields with typed operators, and
  `custom_filter` takes `_or` / `_and` / `_not` groups.
- Read-only SQL views of published content for BI tools (`kiln_reporting_v1`,
  with a role from `mix kiln.reporting.sql`).
- Per-document `noindex` / `nofollow`, and the site's X (Twitter) username
  under **Branding**.
- Change severity: an edit to a safety-relevant field of published content
  asks how much it matters, and the answer is stored on the version.
- Plugins can mount plain-Plug endpoints (`plug_routes/0`) and add
  human-verification providers (`challenge_providers/0`), both new in
  `kiln_plugin` 1.4. **System → Plugins** shows each plugin's health on Hex.
- Admins can move a document to the trash from the content list or the
  editor, and can rotate a webhook's signing secret.

## Changes

- **A console page you lack the role for** now shows a 403 page naming the
  role it needs, instead of sending you home with a toast. `access-denied` is
  a reserved root slug: run `mix kiln.reserved_paths` to find a page using it.
- **Single sign-on, Sessions, Password policy, Blocked addresses and Bot
  budgets** moved to a new **Sign-in & access** section of the sidebar. Their
  addresses are unchanged.
- **Search engines whose address DNS has verified** get 200% of the delivery
  limit by default. Scripts and clients with no user agent are refused sooner
  than before (150 and 60 public-page requests a minute per address).
- **Every `/api/content` and page `ETag` changes once** on this deploy, so
  revalidating clients and CDNs get one round of full responses.
- **An in-app backup whose off-site copy fails** now finishes **Failed**
  instead of succeeding without the copy.
- **Webhook signing secrets** are masked to their last four characters until
  an admin clicks **Reveal**.

## Breaking changes

### Public pages take their language from the URL

**Who is affected:** multilingual sites whose theme styles articles by
`html[lang]`, and links to an unprefixed URL of content that exists only in a
non-default locale (now a 404). On a fallback page, `<html lang>` names the
reader's language and `<article lang>` names the record's.

**Before:**

```css
html[lang="fr"] .public-article h2 { letter-spacing: 0; }
```

**After:**

```css
.public-article:lang(fr) h2 { letter-spacing: 0; }
```

### Unpublishing and archiving need publish rights

**Who is affected:** editors on upgraded sites, and editors' `:read_write`
API keys, which now get `403` on unpublish and archive. Upgraded sites default
to admins-only publishing. To give editors both back, a platform admin clicks
**Let editors publish** under **Team → Publishing**.

### Registering no longer signs the user in

**Who is affected:** front ends and tests that expect `/register` to end
signed in. Everyone is now told to check their email and sent to `/sign-in`,
and an address that already has an account gets no new row (its owner is
emailed instead).

The confirmation link then asks for the password chosen at sign-up. Someone
who doesn't know it is sent to reset the password, which confirms the account
and removes any earlier password, two-step verification, passkeys, API keys
and sessions, so a stranger who registered the address first keeps no way in.
A magic-link sign-in to an unconfirmed account does the same.

### Overlay and plugin code

**Who is affected:** overlays and plugins that call these functions directly.

`Accounts.Bootstrap.create_first_admin/1` returns the breached-password
notices as a third element:

```elixir
# Before
{:ok, admin} = Bootstrap.create_first_admin(attrs)

# After
{:ok, admin, _notices} = Bootstrap.create_first_admin(attrs)
```

`Backups.enqueue/1` returns a status and chain instead of an `Oban.Job`, and
is deprecated for `Backups.request/2`:

```elixir
# Before
{:ok, %Oban.Job{}} = Backups.enqueue()

# After
{:ok, %{status: :started, chain: _chain}} =
  Backups.request([], Backups.system())
```

`restore_<type>_version` refuses a record read before a later write
(`StaleRecord`), and `purge_<type>` / `purge_media_item` refuse a record that
isn't in the trash. Read the record again before restoring, and trash it with
`destroy_<type>` before purging. The revisions restore route answers a lost
race with `409`, not `422`.

## Deprecations

- `Backups.enqueue/1` and `Backups.Worker.run/3` are deprecated. Use
  `Backups.request/2` instead.
- `KILN_API_REJECT_INVALID_BEARER=false` restores the old anonymous fallback
  for this release only.

## Known issues

- **Resume on a failed backup says it is queued but never runs.** Affects a
  Resume asked for while a backup runs and a Resume of another run is already
  queued. Click Resume again once the queued one has finished. Tracked in
  [#2671](https://github.com/The-Verscienta/kiln_cms/issues/2671).
  **Fixed in 1.9.0.** Listed here by mistake: [#2688](https://github.com/The-Verscienta/kiln_cms/pull/2688)
  in this release already refuses that resume with a message naming the
  queued run, and leaves the queue as it was.
- **"Backup resumed", then nothing happens.** Affects clusters where each node
  has its own `BACKUP_DIR`. Resume again until it runs on the node that took
  the backup. Tracked in [#2539](https://github.com/The-Verscienta/kiln_cms/issues/2539).
  **Fixed in the next release.** A resume then runs on a node that has its
  files, and a resume that can't run says "Resume refused: …" on its History
  row ([Backups](../backups.md#several-nodes-and-the-backup-lock)).
- **Backups History shows an "ok" off-site copy for a cron backup that
  failed.** Affects cron failures imported before upgrading. Treat those rows
  as never copied off-site. Tracked in
  [#2485](https://github.com/The-Verscienta/kiln_cms/issues/2485).
- **A cron backup stays "pending" in History forever.** Affects hosts where
  only cron takes backups, after a killed `backup.sh` run. Delete its
  `kiln-media-<stamp>.*.partial` file by hand. Tracked in
  [#2478](https://github.com/The-Verscienta/kiln_cms/issues/2478).
  **Fixed in the next release.** The app then records the stamp as a failed
  "Interrupted" run after 3 quiet hours, and that release's `backup.sh prune`
  removes its `.partial` files after 12
  ([Backups](../backups.md#when-a-cron-run-is-killed-outright-2478)).
- **A custom filter on an email, color, telephone or time field misses values
  written another way (`#FFF` vs `#ffffff`).** Write the operand the way it is
  stored. Tracked in [#2677](https://github.com/The-Verscienta/kiln_cms/issues/2677).
  **Fixed in the next release.** `eq`, `not_eq` and `in` then match the
  operand both as sent and as a save stores it, on single email, color,
  telephone, time, slug, string, URL and select fields
  ([json-api.md](../json-api.md) → "Custom fields").
- **GraphQL `customWhere` with `dateTime` can miss date-time list items saved
  with fractional seconds.** Filter with `custom_filter` on the REST API
  instead. Tracked in [#2678](https://github.com/The-Verscienta/kiln_cms/issues/2678).
- **Renaming a field's section can move or leave its layout wrongly when
  another admin changed the same type meanwhile.** Reload Fields before
  renaming a section. Tracked in
  [#2652](https://github.com/The-Verscienta/kiln_cms/issues/2652).
- **On a site other than the default one, New draft and Translations can be
  offered or hidden by the default site's type scope.** Saving is still
  checked against the right site. Tracked in
  [#2599](https://github.com/The-Verscienta/kiln_cms/issues/2599).
- **Lock and teaser pages, embedded forms and newsletter confirmation mail can
  be in the wrong language on a multilingual site.** No workaround yet.
  Tracked in [#2597](https://github.com/The-Verscienta/kiln_cms/issues/2597).
- **A gallery carousel can't be scrolled with the keyboard.** Use the grid
  layout where that matters. Tracked in
  [#2590](https://github.com/The-Verscienta/kiln_cms/issues/2590).
- **A media item trashed while quarantined, then restored, can still be
  permanently deleted from a media trash page loaded earlier.** Reload the
  media trash before deleting. Tracked in
  [#2610](https://github.com/The-Verscienta/kiln_cms/issues/2610).
- **A restored event can show a stale next occurrence.** Save the event once
  to recompute it. Tracked in
  [#2621](https://github.com/The-Verscienta/kiln_cms/issues/2621).
