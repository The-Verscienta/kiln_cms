# What's new in Kiln 1.13

Below: what Kiln 1.13 adds, what works differently, what to do before you
upgrade, and what is still broken. Every change, one line each, is in the
[1.13.0 changelog](../changelog/unreleased.md).

## At a glance

- **Answer engines** can read a custom field's text: tick **Include in
  AI-readable outputs** on a text, group or flexible field and it joins the
  `:llm` Markdown and the `:json_ld` node.
- **Editors** can search a flexible field's items, and version history now
  lists each item that was added, removed, changed or moved.
- **Admins** can show or require a field when another one contains, starts
  with or ends with some text.
- **Editors** filling in an address get the selected country's own labels and,
  for 62 countries, a list of its states, provinces or prefectures.
- **AI clients on `/mcp`** can no longer put an edit on a live page
  unreviewed: they stage it in the page's working copy, and a person
  publishes it.
- **Headless clients** that send malformed rich text get a `400` naming the
  path, and a malformed body already stored renders again instead of breaking
  the page.

## Before you upgrade

Read the [Upgrade notes and Breaking sections](../changelog/unreleased.md) in
full; `mix kiln.update` prints them, and the known issues, before it moves
your pin. In short:

1. **Run `mix ash.migrate`.** It adds one column,
   `field_definitions.deliver_llm` (`boolean`, `NOT NULL`, default `false`),
   for [AI-readable custom fields](#custom-field-text-in-the-ai-readable-outputs).
   Rolling back is safe: an older release ignores the column. No other
   change in 1.13 needs a migration.
2. **Headless clients that write rich text** read the
   [breaking change below](#malformed-portable-text-in-block_tree-is-a-400).
   A `:json` consumer can see the shape of an old malformed body change on its
   next fire, and sending back an artifact fired before then can be a `400`. A
   draft of such a live record that was pending across the upgrade can show a
   conflict on **Blocks** when it is published: choose **Use mine**, or
   discard it and save it again
   ([upgrade note](../changelog/unreleased.md#portable-text-write-check-upgrade)).
3. **If you ran `mix kiln.links.backfill` on 1.5.0 to 1.12.1, run it again.**
   It had deleted every list reference edge, and on 1.12.1 every reference
   edge in a group or flexible item. Nested edges come back when each record's
   custom fields next change
   ([upgrade note](../changelog/unreleased.md#links-backfill-multiple-upgrade),
   [how to](../extending-content.md#rebuild-the-reference-edges-from-stored-values)).
4. **Check drafts saved before a field rename.** A draft of a live record
   saved before a custom field was renamed or deleted, on 1.0.0 to 1.12.1,
   still holds the old key, and publishing it still drops that value.
   Re-enter it or discard the draft
   ([upgrade note](../changelog/unreleased.md#rename-rewrites-working-copies-upgrade)).
5. **Check the audiences of waiting and rejected registrations.** On 1.9.0 to
   1.12.1, saving the audiences panel for one could remove its audiences, so
   those registrations, and accounts approved since, may lack audiences you
   gave them. Re-tick them; Kiln can't restore them
   ([upgrade note](../changelog/unreleased.md#audiences-panel-stored-upgrade)).
6. **Rolling deploys with direct uploads.** Until every node runs 1.13, a
   completion handled by an older node can still lose its staged object to the
   cleanup job. A token whose cleanup job was never queued now answers
   `422 not_uploaded`
   ([upgrade note](../changelog/unreleased.md#direct-upload-claim-upgrade)).
7. **MCP clients and `:mcp_tools` overrides.** An MCP client that edited
   published records with `update_*` must switch to the working-copy tools,
   and a project that overrides `config :kiln_cms, :mcp_tools` must add
   `save_page_working_copy`, `save_post_working_copy` and
   `save_entry_working_copy` ([below](#mcp-edits-to-a-published-record-wait-for-a-person)).
8. **`scripts/staging.sh up` and `down`** now need `STAGING_DATABASE_URL` as
   a URL naming the database in its path, refuse a database name without
   `staging`, `preview`, `ephemeral`, `tmp` or `scratch` unless
   `KILN_STAGING_FORCE` is on, and act on the URL's server, not libpq's default
   one ([long form](../changelog/unreleased.md#staging-script-guards-drop)).
9. **Gated HTML pages follow site membership.** A signed-in reader's gated
   pages, posts and entries now open from the audiences on their active
   membership on that site, the same rule the API already follows. Audiences
   held only on the account (from before per-site memberships, or set outside
   the console) no longer open HTML pages. Run `mix kiln.deprecations` (or
   `bin/kiln_cms eval 'KilnCMS.Release.deprecations()'`) to list them, and grant
   them per site from the account page's audiences panel
   ([upgrade note](../changelog/unreleased.md#delivery-site-membership-audiences-upgrade)).

## New features

### Custom field text in the AI-readable outputs

Answer engines read two fired artifacts, the `:llm` Markdown and the
`:json_ld` node, and until now neither carried a custom field. A text, group
or flexible field can now opt in, so an FAQ built from flexible items reaches
them. It is off by default, so nothing existing changes until you tick it.

**In the console:** `/editor/fields` → **Edit** on a top-level
text, group or flexible field → tick **Include in AI-readable outputs** →
save (admins only). The row shows an **AI-readable** badge, and the type's
published documents re-fire.

For a post with a flagged `FAQ` flexible field (item type `Question and
answer`, with `Question` and `Answer` text sub-fields) and a flagged
`Editor note` text field, the `:llm` artifact
(`/api/content/post/<slug>?surface=llm`) ends with:

```markdown
## FAQ

### Question and answer

**Question:** Why?

**Answer:** Because.

## Editor note

Read me
```

and the `:json_ld` main node (`?surface=json_ld`) gains:

```json
"hasPart": [
  {"@type": "WebPageElement", "name": "Question and answer", "text": "Why?\n\nBecause."},
  {"@type": "WebPageElement", "name": "Editor note", "text": "Read me"}
]
```

A flagged group or flexible field sends every text sub-field except one
marked **Setting**, and that text becomes public. A private field can't be
flagged. (Output copied from `test/kiln_cms/firing/deliver_llm_test.exs`.)

Read more: [Put custom field text in the AI-readable outputs](../extending-content.md#put-custom-field-text-in-the-ai-readable-outputs).

### Searchable flexible fields, and their history item by item

A flexible field can now be searchable, so search finds a record by the text
in its items. Version compare and the restore preview list each item that was
added, removed, changed or moved, instead of two walls of JSON.

**In the console:** when you add a flexible field in `/editor/fields`, tick
**Searchable (search indexes this value as text)** before **Add field**
(admins only). Search indexes each item's text, never its `_id`, `_type` or
`_settings`, and never a **Media** or **Reference** sub-field. Flipping the
flag re-fires the type's published documents.

**In history:** open a record's version **Compare**, or start a **Restore**.
The flexible field lists one row per item that changed, with its item type's
label and its text before and after; an item that only changed place carries
a **Moved** pill.

**In code**, `KilnCMS.CMS.VersionDiff` gives such an entry an `items` list.
Two items whose order was swapped, one of them edited:

```elixir
item = fn id, type, extra -> Map.merge(%{"_id" => id, "_type" => type}, extra) end
old = [item.("a", "hero", %{"headline" => "One"}), item.("b", "quote", %{"text" => "Q"})]
new = [item.("b", "quote", %{"text" => "Q"}), item.("a", "hero", %{"headline" => "Two"})]

KilnCMS.CMS.VersionDiff.between(
  %{"custom_fields" => %{"sections" => old}},
  %{"custom_fields" => %{"sections" => new}},
  KilnCMS.CMS.Page
)
# the "sections" entry's items:
# [%{id: "b", type: "quote", status: :unchanged, moved?: false, old_index: 1, new_index: 0,
#    changed_keys: [], old: …, new: …},
#  %{id: "a", type: "hero", status: :changed, moved?: true, old_index: 0, new_index: 1,
#    changed_keys: ["headline"], old: …, new: …}]
```

Before you roll back past 1.13: an older release refuses to save a flexible
definition marked `searchable` until the flag is cleared, and refuses a
field-sync file with `"searchable": true` on a flexible field.

Read more: [Search a flexible field and read its history](../extending-content.md#search-a-flexible-field-and-read-its-history).

### Conditions that match text

A **Show when** or **Required when** test can now read text: "show **Download
notes** when **File URL** ends with `.pdf`". Matching ignores case and
surrounding spaces. On a field that holds a list, the test holds when any item
matches.

**In the console:** `/editor/fields` → a field → **Conditions** → pick a text, URL or
choice field to test, then **contains**, **does not contain**, **starts with**
or **ends with**, and the text (admins only).

**In a rule**, the operators are `contains`, `not_contains`, `starts_with` and
`ends_with`, each with a non-blank string `value`. This one makes a `contact`
field required when the `site` URL starts with `http://`; the server decides
it too, so `HTTP://example.com` without a contact is refused with `is
required`:

```elixir
%{"field" => "site", "op" => "starts_with", "value" => "http://"}
```

A rule that tests a number, yes/no or date field this way is refused with
`can't match text in <field>: it is not a text, URL or choice field`. (Rule
copied from `test/kiln_cms/cms/field_conditions_test.exs`.)

Read more: [Make a field conditional](../extending-content.md#make-a-field-conditional).

### Address fields that know the country

An address field's editor now follows the selected country. Pick the US and
the parts read **State** and **ZIP code**; the UK has a **County** and a
**Postal code**; Japan a **Prefecture**. A part the country doesn't use isn't
offered unless the stored address already has one. For 62 countries the
administrative area is a select, and the address stores the area's code.

The server is lenient: a name or a lower-case code is converted on save, and
text that matches nothing is kept as typed, so existing values, imports and
API clients keep working:

```elixir
KilnCMS.CMS.FieldTypes.Address.cast(
  %{"country" => "US", "administrative_area" => "California", "locality" => "Sacramento"},
  %{}
)
#=> {:ok, %{"administrative_area" => "CA", "country" => "US", "locality" => "Sacramento"}}

KilnCMS.CMS.FieldTypes.Address.cast(%{"country" => "GB", "administrative_area" => "England"}, %{})
#=> {:ok, %{"administrative_area" => "England", "country" => "GB"}}
```

A `searchable` address field indexes the stored code, not the area's name.
An address saved before 1.13 is converted the next time it is saved.

Read more: [Address fields](../extending-content.md#address-fields).

### Malformed rich text can't break a page

A rich-text body stored in a malformed Portable Text shape (`marks` as a
string, `children` that aren't spans, a `markDefs` entry that isn't an object)
used to make the public page answer 500, firing fail, and the record
impossible to save again. Now every reader repairs the body before using it:
a string `marks` becomes a one-item list, a string child becomes a span, and
what holds no text is skipped. The page renders, fires and is indexed again.
The stored row isn't rewritten.

On the write side, a headless write with such a body is refused with the
path, so a client learns at write time that its body is wrong. Restore,
promote, copy and import write back what is already stored, so they repair a
body rather than refuse it. A plugin block's `:rich_text` field gets the same
check, repair and link scrub. What is refused, with the request before and
after, is under [Breaking changes](#malformed-portable-text-in-block_tree-is-a-400).

Read more: [Portable Text in `block_tree` is checked](../json-api.md#block-tree-portable-text-check)
and [ADR 0083](../decisions/0083-a-portable-text-body-is-checked-against-its-published-schema-at-block-tree-and-repaired-elsewhere.md).

## Changes

### MCP edits to a published record wait for a person

Over `/mcp`, `update_page`, `update_post` and `update_entry` now refuse a
published record, for every key, an admin's included. They answer
`isError: true` with `this record is published, and MCP edits never go live
directly; use the save_*_working_copy tool to stage the change for a person
to publish`, and write nothing. Drafts, records in review and archived
records are edited with `update_*` as before.

**Use instead:** `save_page_working_copy`, `save_post_working_copy` and
`save_entry_working_copy`. They take `title`, the body as `block_tree` or
`body_markdown`, and `fields` for the other held settings, and refuse a record
that isn't published.

**Before** (1.12.1, the live page changed at once):

```json
{"name": "update_page", "arguments": {"id": "<page id>",
  "input": {"title": "Held title"}}}
```

**After:**

```json
{"name": "save_page_working_copy", "arguments": {"id": "<page id>",
  "input": {
    "title": "Held title",
    "body_markdown": "A **held** paragraph.",
    "fields": {"seo_description": "Held description"}}}}
```

Readers keep the published text. In the editor the page's state pill reads
**Live · draft** until someone with an editor or admin account clicks
**Publish changes**. JSON:API, GraphQL and in-context editing still edit a
live record directly. (Calls copied from `test/kiln_cms_web/mcp_test.exs`,
"live records".)

Read more: [Edit a published page from an MCP client](../mcp.md#edit-a-published-page-from-an-mcp-client).

### Also different

- **The visual-editing preview read encodes only prose.** Before, it appended
  its invisible field address to almost every string on a block, so a video's
  `src`, a file's `download_url` or a media id came back unusable. Now only
  prose is encoded: the title, rich-text spans, and the fields a block type
  declares as plain-text prose. A value that reads as a URL, path, UUID or
  identifier never is
  ([visual-editing-bridge.md](../visual-editing-bridge.md)).
- **A list field's errors count items from 1.** A value rule now says
  `Scores (scores) item 2 must be at most 10` instead of
  `Scores (scores[1]) …`. JSON:API `code`/`source.pointer` and GraphQL
  `code`/`fields` are unchanged
  ([long form](../changelog/unreleased.md#list-item-error-position)).
- **Renaming, deleting or reshaping a custom field reaches the drafts of live
  records,** so *Publish changes*, a release or an unpublish no longer reports
  a conflict nobody made. Open editors see "changed elsewhere" once, and an
  `If-Match` client gets one `412` ([working-copy.md](../working-copy.md)).
- **Release times after scheduling are shown in UTC and say so**
  (`2026-11-25 14:00 UTC`); you still type **Go live at** in your browser's
  local time ([content-releases.md](../content-releases.md)).
- **A document whose parent is in the trash shows on the structure page,**
  marked **Parent unavailable**, and can be moved
  ([trash.md](../trash.md#children-of-a-trashed-document)).
- **Content-list actions on a row someone else trashed** show a message, and
  the bulk bar reports the rest, e.g. "Publish: 3 updated, 1 no longer exists".
- **The Visual button and a preview block's Edit link keep your
  translation;** before, a `fr` variant's edits could land on the `en` record
  ([visual-editing-bridge.md](../visual-editing-bridge.md)).
- **An API key minted by a newer release with a scope this one doesn't know**
  is refused at sign-in like a revoked key, and the security posture warns
  ([security-posture.md](../security-posture.md)).
- **A blank or unreadable `PORT`, `POOL_SIZE`, `SMTP_PORT` or
  `S3_ENDPOINT_PORT`** keeps its default and warns, instead of crashing boot.
- **Files over 16 MB reach S3 on a slow uplink.** Each part gets time in
  proportion to its size and is retried before the upload is aborted. New
  variable `S3_UPLOAD_MIN_BYTES_PER_SECOND`, default `32768`
  ([environment-variables.md](../environment-variables.md)).
- **Large WordPress, Ghost and envelope imports keep their media.** Each image
  download has its own 60-second deadline, and an unresponsive host is skipped
  after three timeouts in a row.
- **The daily health sweep reaches every overdue and expired record,** not
  the same 500 per type each day. A site with a large backlog gets many more
  `health_overdue` and `health_expired` events, and the automation jobs they
  start ([content-lifecycles.md](../content-lifecycles.md)).
- **A newsletter campaign's Sent and Failed add up** after retries (see
  *Read a campaign's counts* in [newsletter.md](../newsletter.md)).
- **A webhook endpoint is no longer switched off by a miscount,** and the
  "switched off" alert fires once ([webhooks.md](../webhooks.md)).
- **`mix kiln.gen.content Story --plural stories`** serves at `/stories`.
  Types generated before keep `storys` until you add `plural:` by hand
  ([extending-content.md](../extending-content.md)).
- **A Slug field offers the Unique box** in `/editor/fields`, and saving a
  field no longer drops a constraint the form didn't post.

## Breaking changes

### Malformed Portable Text in `block_tree` is a `400`

**Who is affected:** headless clients that write rich text through JSON:API
`block_tree`, GraphQL `blockTree`, or the MCP `create_*`, `update_*` and
`save_*_working_copy` tools, and plugins whose blocks declare a
`field :x, :rich_text`. To check, look at what your client puts in a
`rich_text` block's `body` and in any plugin `:rich_text` field.

These shapes were stored on 1.12.1 and are refused now, with nothing written:

- a `marks` entry that is an object or a list;
- an object or list in a text block's `style`, `listItem` or `_key`, or in a
  span's `_key`;
- a text block's `level` that isn't a whole number or a numeric string
  (`"two"`, `2.5`, `true`);
- a plugin block's `:rich_text` field holding malformed Portable Text, by the
  same rules as a `rich_text` body.

A number or boolean in a text slot, and a numeric-string `level`, are still
coerced, and a `null` entry in `marks` is dropped.

**Before** (1.12.1 stored this and ignored the mark when rendering):

```http
POST /api/json/posts
Content-Type: application/vnd.api+json

{"data": {"type": "post", "attributes": {"title": "T", "slug": "t",
  "block_tree": [{"_type": "rich_text", "body": [
    {"_type": "block", "_key": "b0", "style": "normal", "markDefs": [],
     "children": [{"_type": "span", "text": "Bold", "marks": [{"x": 1}]}]}]}]}}}
```

1.13 answers `400`:

```json
{
  "errors": [{
    "status": "400",
    "code": "invalid_attribute",
    "source": {"pointer": "/data/attributes/block_tree"},
    "detail": "is not valid Portable Text: block_tree[0].body[0].children[0].marks[0] must be a string (got an object)"
  }]
}
```

GraphQL returns the same message in the mutation's `errors` with a `null`
`result`, and an MCP tool answers `isError: true` with it.

**After:** send `marks` as a list of strings:

```json
"children": [{"_type": "span", "text": "Bold", "marks": ["strong"]}]
```

Send a text block's `style`, `listItem` and `_key` and a span's `_key` as
strings, and `level` as an integer. (Body and error copied from
`test/kiln_cms_web/portable_text_write_check_test.exs`.)

Read more: [Portable Text in `block_tree` is checked](../json-api.md#block-tree-portable-text-check),
with the steps to fix a refused body. Why a minor release may refuse this:
[ADR 0084](../decisions/0084-a-minor-release-may-tighten-a-documented-write-when-the-old-input-corrupted-data-or-bypassed-review.md).

## Security

1.13.0 fixes three issues, each with a repository advisory. Upgrade to get the
fixes; none needs a configuration change, and the second has the upgrade step
above.

- **External programs stop when they should**
  ([GHSA-h3hm-8ff5-wr4v](https://github.com/The-Verscienta/kiln_cms/security/advisories/GHSA-h3hm-8ff5-wr4v)).
  A deadline, a canceled or fenced backup step, or the death of its job now
  stops qpdf, ffmpeg/ffprobe, `pg_dump`, `pg_restore`, `tar`, `rclone` or `df`,
  and the program's own children, in the official image. Affects 0.6.0 to
  1.12.1. A custom entrypoint that leaves another program as PID 1 should use an
  init such as `tini`
  ([long form](../changelog/unreleased.md#external-command-group-kill)).
- **Gated HTML follows the reader's membership on the site**
  ([GHSA-4m98-m3c9-7cwx](https://github.com/The-Verscienta/kiln_cms/security/advisories/GHSA-4m98-m3c9-7cwx)).
  Gated pages, teasers and paywalls take the reader's audiences from their
  active membership on the site serving the request, as the API and the read
  policies already do. Affects 0.5.0 to 1.12.1
  ([long form](../changelog/unreleased.md#delivery-site-membership-audiences)).
- **Markdown mode caps list depth**
  ([GHSA-ffw4-2w7m-xh53](https://github.com/The-Verscienta/kiln_cms/security/advisories/GHSA-ffw4-2w7m-xh53)).
  The content editor's Markdown mode writes a list item at most 10 levels deep,
  however large its stored `level`. Affects 1.0.0 to 1.12.1
  ([long form](../changelog/unreleased.md#portable-text-list-level-cap)).

## Known issues

- **A document published again within seconds of its last publish can keep
  serving the earlier version.** Affects any site: a second publish or edit
  that lands while the first fire job is still running is dropped as a
  duplicate, so delivery, search and embeddings keep the older text. Until it
  is fixed, publish the document once more after a minute, or run
  `mix kiln.refire_all`.
  ([#3360](https://github.com/The-Verscienta/kiln_cms/issues/3360))
- **A duplicated text block saves empty, though the editor still shows its
  text.** Affects editors who duplicate a rich-text block and then type
  anywhere before saving. Until it is fixed, add a new text block and paste
  the text instead of duplicating, or re-check the copy after saving.
  ([#2778](https://github.com/The-Verscienta/kiln_cms/issues/2778))
- **In the Presentation console, an unsaved edit to a block is lost when you
  open another block and come back.** Affects anyone editing in the
  Presentation console; the next keystroke writes the saved text back over
  the edit. Save each block before opening the next one.
  ([#3376](https://github.com/The-Verscienta/kiln_cms/issues/3376))
- **Unsaved edits in a related-record card are lost when you trash the page
  or use Publish changes or the Publish confirm.** Affects reference fields
  with "Let editors edit the related record here"; only Save and workflow
  steps save the cards first. Save the cards (or press Save) before trashing
  or publishing.
  ([#3256](https://github.com/The-Verscienta/kiln_cms/issues/3256))
- **Video, audio and file blocks in a newsletter email link nowhere.**
  Affects every newsletter campaign with such blocks: the email carries
  relative `/media/...` links. Until it is fixed, link the file's full URL in
  a text block instead.
  ([#3290](https://github.com/The-Verscienta/kiln_cms/issues/3290))
- **Restoring a version saved before a custom field was renamed leaves that
  field empty.** Affects version restore and release rollback after a field
  rename; the old key is dropped with a log warning. Copy the value from the
  version compare before restoring and re-enter it afterwards.
  ([#3371](https://github.com/The-Verscienta/kiln_cms/issues/3371))
- **A site whose custom domain was saved with capital letters is unreachable
  on that domain.** Affects site admins on multi-site installs; requests fall
  back to the default site, or are refused under strict host matching, with
  no error at save. Enter the custom domain in lower case.
  ([#3281](https://github.com/The-Verscienta/kiln_cms/issues/3281))
- **After a site's slug or custom domain changes, published pages keep
  linking to the old host.** Affects bylines and other absolute URLs in fired
  artifacts until each document is published again. Run
  `mix kiln.refire_all` after the change.
  ([#3282](https://github.com/The-Verscienta/kiln_cms/issues/3282))
- **A page slugged `developers`, `sitemap.xml`, `llms.txt`, `ready` or a few
  other built-in names saves, but its address shows the built-in page.**
  Affects editors choosing those slugs; nothing warns. Pick another slug or
  path alias.
  ([#2898](https://github.com/The-Verscienta/kiln_cms/issues/2898))
- **A site storage profile on a region ExAws doesn't know (Backblaze B2
  `us-west-004`, Wasabi `us-central-1`) fails on every upload and read; keep
  such sites on the instance's storage until the fix.**
  ([#3085](https://github.com/The-Verscienta/kiln_cms/issues/3085) · [long form](../changelog/v1.12.0.md#site-storage-unknown-region))
- **A page opened at its path alias shows no reference byline and leaves
  inherited (`:fallback`) fields blank, though the same page at its slug shows
  both; link to the slug where that matters.**
  ([#3193](https://github.com/The-Verscienta/kiln_cms/issues/3193) · [long form](../changelog/v1.12.0.md#alias-page-bylines-fallback))
- **A release preview shows a fragment's currently published body, not the
  version the same release will publish; open the target's own entry in the
  preview to review it.**
  ([#3289](https://github.com/The-Verscienta/kiln_cms/issues/3289) · [long form](../changelog/v1.12.1.md#release-preview-fragments))
- **With many Hex plugins and a hex.pm that stays slow, the same plugins at
  the end of the list read Unknown on every plugin check; check those on
  hex.pm by hand.**
  ([#3165](https://github.com/The-Verscienta/kiln_cms/issues/3165) · [long form](../changelog/v1.12.0.md#plugin-health-tail-packages-unknown))
- **An image in the middle of a line of Markdown disappears, alt text
  included, with no error.** Affects Markdown to Blocks, `body_markdown`
  writes and imports that go through it. Put each image on its own line.
  ([#2771](https://github.com/The-Verscienta/kiln_cms/issues/2771))
- **After `mix kiln.import.content`, body images still load from the old
  site.** Affects envelope imports with a media manifest: those images are
  never copied, and media usage doesn't track them. Keep the old site's media
  online, or re-upload and re-insert those images.
  ([#3326](https://github.com/The-Verscienta/kiln_cms/issues/3326))
- **A form field named `slug` stores the form's own slug instead of the
  visitor's answer.** Affects any form with a field whose machine name is
  `slug`. Rename the field (for example to `page_slug`).
  ([#3273](https://github.com/The-Verscienta/kiln_cms/issues/3273))
- **On a site with its own storage bucket, its logo and images don't show on
  form thank-you and error pages or on `/newsletter`.** Affects sites with a
  site storage profile: those pages' policy doesn't allow the bucket. No
  workaround short of serving those images from the instance's storage.
  ([#3266](https://github.com/The-Verscienta/kiln_cms/issues/3266))
- **A large video uploaded to a server with a slow upload link never
  finishes processing.** Affects instances on S3 where stripping and
  re-uploading the file takes over 10 minutes; every retry is killed the same
  way. Upload a smaller or pre-stripped file, or from a host with a faster
  uplink.
  ([#3337](https://github.com/The-Verscienta/kiln_cms/issues/3337))
- **`scripts/restore.sh` with a remote `RESTORE_DATABASE_URL` creates the
  database on the local default server, and the drill's closing `dropdb` hint
  points there too.** Affects operators restoring to another host. Create the
  target database on that server yourself first, and drop the drill database
  with a connection to the target server.
  ([#3329](https://github.com/The-Verscienta/kiln_cms/issues/3329))
- **An admin who publishes a draft from the content list, the bulk bar or a
  release isn't shown the editor's scheduled unpublish date.** Affects sites
  where editors may not publish; the page later comes down at that date. Open
  the draft in the editor to check "Scheduled unpublish at" before approving
  it.
  ([#2892](https://github.com/The-Verscienta/kiln_cms/issues/2892))
